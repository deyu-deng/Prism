# 计划编写模式已激活

## 目标

创建详细的、可执行的实施计划，将工作分解为可验证的垂直切片。

## 执行步骤

### 步骤 1：定义成功标准

"完成"是什么样子的？列出具体的、可衡量的结果：

```markdown
## 成功标准
- 功能 X 在输入 Y 时正常工作
- 测试覆盖率 > 80%
- 响应时间 < 200ms
- 现有功能无回归
- TypeScript 编译零错误
- ESLint 零 warning
```

### 步骤 2：任务分解（垂直切片）

将工作拆分为独立的、可交付的切片：

```markdown
## 实施计划：[功能名称]

### 切片 1：基础层 [优先级: P0]
**目标**: [本切片达成的目标]
**任务**:
- [ ] 任务 1.1: [具体动作项]
- [ ] 任务 1.2: [具体动作项]
**交付物**: [具体产出物]
**依赖**: 无
**预估**: [时间]

### 切片 2：核心逻辑 [优先级: P0]
**目标**: [本切片达成的目标]
**任务**:
- [ ] 任务 2.1: ...
**交付物**: [具体产出物]
**依赖**: 切片 1
**预估**: [时间]

### 切片 3：完善打磨 [优先级: P1]
...
```

### 步骤 3：识别风险

为每个任务标注风险：

- 技术风险：不确定的 API、性能顾虑
- 依赖风险：等待外部服务、其他团队
- 范围风险：需求可能变化

### 步骤 4：定义检查点

在哪里验证进度？

```markdown
## 进度检查点
- 切片 1 完成: [验证方式]
- 切片 2 完成: [验证方式]
- 最终验收: [完整验收标准]
```

## 切片原则

每个切片必须满足：
- ✅ 可以独立交付和演示
- ✅ 包含从数据层到 UI 层的完整链路
- ✅ 有明确的完成定义（Done Definition）
- ✅ 预估时间 < 2 小时
- ✅ 依赖关系清晰标注
- ✅ 不依赖并行任务的内部细节
- ✅ 边界情况被显式指出
- ✅ 高风险变更存在回滚策略

## Prism 集成

编写计划后：
1. 调用 `prism_update_task` 创建任务条目
2. 更新 TASK.md 写入计划内容
3. 向用户展示计划摘要并询问：
   ```
   [[PRISM_QUESTION]]
   type: confirm
   title: "实施计划确认"
   这个计划看起来正确吗？需要调整什么？
   [/PRISM_QUESTION]]
   ```

## 质量检查清单

- [ ] 每个任务足够小（< 2 小时可完成）
- [ ] 依赖关系清晰标注
- [ ] 无任务依赖并行任务的内部细节
- [ ] 边界情况显式列出
- [ ] 高风险变更有回滚策略
- [ ] 切片是垂直的（非水平分层）
- [ ] 成功标准可量化验证

## 反模式（禁止）

- [ ] 水平切片（"先做所有数据层，再做所有 UI"）
- [ ] 任务粒度太大（单个任务 > 半天）
- [ ] 未识别依赖关系
- [ ] 跳过风险评估
- [ ] 没有明确的完成标准
- [ ] 切片间存在循环依赖
