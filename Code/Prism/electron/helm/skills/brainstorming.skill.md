# 头脑风暴模式已激活

## 目标

在 committing 到单一方案之前，生成多个解决方案供选择。

## 执行方法

对于给定任务，产生 **3 个不同的方案**：

### 方案 A：最直观方案
- 最直接的实现方式
- 优点：快速实现、易于理解
- 缺点：可能无法扩展、可能存在技术债务

### 方案 B：稳健方案
- 关注可靠性和可维护性
- 优点：架构清晰、测试充分
- 缺点：耗时较长、对简单需求可能过度工程化

### 方案 C：创新方案
- 利用现代模式或非常规方法
- 优点：潜在竞争优势、学习机会
- 缺点：风险较高、团队可能不熟悉

## 每个方案必须包含的内容

1. **架构概述**：高层结构描述（2-3 句话）
2. **关键组件**：需要的主要模块/类/函数
3. **权衡分析**：获得什么 vs 牺牲什么
4. **工作量估算**：T-shirt 尺寸（S/M/L/XL）
5. **风险点**：可能出什么问题
6. **技术栈影响**：是否需要新增依赖

## 输出格式

```markdown
## 头脑风暴结果：[任务名称]

### 方案 A：[名称]
[详细描述]

**架构**: ...
**组件**: ...
**权衡**: ...
**估算**: S/M/L/XL
**风险**: ...

### 方案 B：[名称]
[详细描述]

### 方案 C：[名称]
[详细描述]

## 推荐
基于当前上下文，我推荐 **方案 X** 因为...
```

## Prism 集成

生成方案后：
1. 调用 `prism_ask_user`，参数如下：
   - questionType: `"choice"`
   - title: `"请选择实现方案"`
   - options: `[方案A, 方案B, 方案C]`
2. **等待用户选择后再进入下一个 skill**
3. 如果用户选择了"其他想法"，通过 input 类型收集详细信息

## 质量检查清单

- [ ] 三个方案确实不同（不是同一方案的变体）
- [ ] 每个方案都给出了具体的技术路径
- [ ] 权衡分析客观（不过度美化某个方案）
- [ ] 工作量估算合理
- [ ] 风险点具体且可验证
- [ ] 推荐方案有明确的理由支撑

## 反模式（禁止）

- 只给出一个方案（"这是最好的做法"）
- 方案之间没有真正的取舍差异
- 忽略现有代码库的约束条件
- 推荐方案与实际推荐理由不一致
- 跳过头脑风暴直接进入计划编写
