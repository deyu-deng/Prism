# 代码审查模式已激活

## 目标

使用多个审查维度对已实现的代码进行系统性自我审查。

## 审查维度（按顺序应用）

### 维度 1：正确性（5 分钟）

- [ ] 代码是否实现了预期功能？
- [ ] 边界情况是否处理？
- [ ] 错误路径是否有测试覆盖？
- [ ] 是否可能出现差一错误（off-by-one）？

验证手段：
```bash
# 运行功能测试套件
npm test -- --grep "[功能名称]"

# 检查 TypeScript 编译错误
npx tsc --noEmit
```

### 维度 2：安全性（3 分钟）

- [ ] 是否存在输入校验？
- [ ] SQL/命令注入是否可能？
- [ ] 认证/授权是否正确？
- [ ] 敏感信息是否被日志记录或暴露？

安全检查清单：
- [ ] 用户输入是否经过清洗？
- [ ] 文件路径是否经过校验？
- [ ] 环境变量是否未被硬编码？
- [ ] 是否使用了 `eval()` 或危险动态代码？

### 维度 3：性能（3 分钟）

- [ ] 是否存在 O(n²) 或更差的算法？
- [ ] 是否有不必要的循环或内存分配？
- [ ] 数据库查询是否已优化（N+1 问题）？
- [ ] 大文件是否全量加载而可以使用流式处理？

性能优化建议：
- 使用 `.filter(Boolean)` 过滤空值后再 map
- 使用 Set 替代 Array.includes 进行查找
- 懒加载重量级依赖
- 大列表使用虚拟滚动

### 维度 4：可维护性（5 分钟）

- [ ] 6 个月后其他人能否读懂这段代码？
- [ ] 函数名是否准确描述了行为？
- [ ] 复杂逻辑是否有注释解释？
- [ ] 魔法数字是否提取为命名常量？

命名审计：
```
Bad: handleData(x, y, z)
Good: processUserRegistration(email, password, profile)
```

### 维度 5：测试质量（3 分钟）

- [ ] 测试是否覆盖了关键路径？
- [ ] 断言是否有意义（不只是 `.toBeTruthy()`）？
- [ ] 边界情况是否覆盖？
- [ ] 测试是否独立（无共享可变状态）？

### 维度 6：文档完整性（2 分钟）

- [ ] 公共 API 是否有文档注释？
- [ ] 复杂算法是否有解释？
- [ ] 如果面向用户，README 是否更新？
- [ ] 重要决策是否写了 ADR？

## 输出格式

审查完成后，生成以下格式的总结：

```markdown
## 代码审查报告：[功能/文件]

✅ **通过项**: [看起来不错的部分]
⚠️ **警告项**: [非阻塞但需跟踪的问题]
🐛 **发现问题**: [必须修复的问题]

### 问题列表（按优先级排序）

#### 1. [P0-致命]: [问题描述]
   - 位置: [文件:行号]
   - 修复建议: [具体建议]

#### 2. [P1-应当]: [问题描述]
   - 位置: [文件:行号]
   - 修复建议: [具体建议]

### 指标
- 变更文件数: N
- 新增行数: N
- 删除行数: N
- 测试覆盖率: N%
- 复杂度评分: N/10

### 审查结论
- [ ] **通过**: 可以合并/部署
- [ ] **有条件通过**: 先修复 P0 问题
- [ ] **需要返工**: 需要重大修订
```

## Prism 集成

审查完成后：
- **如果通过**：调用 `prism_write_decision` 记录审查结果
- **如果发现问题**：创建修复任务，不要自动提交
- **始终**调用 `prism_ask_user` 向用户展示审查摘要并请求人工签字确认

## 审查反模式

- [ ] 走马观花式审查（只看代码不看测试）
- [ ] 只关注代码风格忽略逻辑错误
- [ ] 发现问题但不给出修复建议
- [ ] 跳过安全性审查（"这只是内部工具"）
- [ ] 不检查边界情况和异常路径
